# $HOME

The layout of `/home/meow`, and the rules that decide where a new thing goes.
Symlinked to `~/CLAUDE.md` — an agent working anywhere under `$HOME` reads this
first. Linked by `scripts/bash/bootstrap.sh`, kept linked by `home_setup.sh`.

```
~
├── git/          every repo I clone or write            14 repos
├── ben/          me: papers, keys, CV, photos           115M
├── archive/      cold bulk, mirrored to sarten          1.9T
├── downloads/    staging, empties monthly
├── desktop/      steam-generated .desktop launchers
├── vm/           ISOs for virtualisation                 25G
└── wine/         wine prefixes + their installers       2.7G
```

Seven directories. Nothing else at root but dotfiles and two symlinks
(`.zshenv`, `CLAUDE.md`), both into `git/dots`.

## The one rule

**Top level is lifecycle, not file type.** There is no `Documents/` or
`Pictures/`. A thing's folder is decided by *what happens to it next*: it gets
committed (`git`), it identifies me (`ben`), it sits still and gets backed up
(`archive`), or it is about to be triaged (`downloads`). Ask "what do I do with
this?", never "what kind of file is this?".

## What goes where

| Dir | Goes in | Never goes in | What removes it |
| --- | --- | --- | --- |
| `git/` | anything under version control, one repo per child | build output, bulk media, anything >1G | `rm -rf`, it's re-clonable |
| `ben/` | passport, certs, CV, pass store, wallet, my photos | anything I'd publish, anything regenerable | nothing — this is the irreplaceable tier |
| `archive/` | finished media, roms, games, wallpapers, backups | live service state, WIP, anything a program writes to | pruned by hand when a category outgrows its use |
| `downloads/` | whatever the browser and torrent client just wrote | anything I've decided to keep | monthly — if it's still here it wasn't wanted |
| `desktop/` | nothing by hand; steam writes here | anything I put there myself | regenerated by steam |
| `vm/` | install ISOs | disk images (those are incus', on sarten) | when the release is superseded |
| `wine/` | one prefix per app under `prefix/`, its installer under `installer/` | anything that isn't a windows app's state | when I stop using the app |

The fourth column is the one that matters. A folder without an answer there
grows forever — that's how `archive/other/` reached 322G.

anything in two levels and `yazi ~/git` shows the whole surface at once.

together. If a third shows up, they get flattened.

wrote. Different things, same word — check which one you want.

## archive/

Its own `CLAUDE.md` and `.gitignore` govern it. The short version: only
`scripts/` and `docs/*.md` are tracked (jj, colocated git), everything else is
bulk. Categories are siblings, one level deep:

```
archive/
├── media/        anime book movies music series youtube   463G
├── roms/         one dir per system, bios/ shared         532G
├── games/        PC ports, mods, standalone, vn/          473G
├── programs/     installers I keep                         30G
├── wallpaper/                                              12G
├── backup/       phone, bookmarks, calendar, kiwix, maps  162G
├── inbox_2026-09 unsorted, dated — see below              120G
├── knowledge/    wikis, maps
├── docs/         *.md wishlists + ebooks
└── scripts/      flat, category_description.py
```

**`inbox_2026-09` is the only unsorted folder allowed, and the date is the
point.** It was `1_fix` and sat at 120G because a name with no deadline is
permanent storage wearing a to-do's clothes. The rule now: an inbox carries the
month it opened, and a second one may not be created while an older one exists.
Either it drains into a real category or it gets deleted — the date makes which
one obvious.

`db/monero` used to live here; it was a live node's 222G lmdb, which is service
state, not archive. It's at `~/.local/share/monero` now.

## New machine

```bash
curl -fsSL https://gitlab.com/asynthe/dots/-/raw/main/scripts/bash/bootstrap.sh | bash -s -- --apply
```

Clones this repo to `~/git/dots` over https (remotes switched to ssh after),
links `~/CLAUDE.md` to this file, then runs `home_setup.sh`. Drop `--apply`
for a dry run; prefix `nix-shell -p git --run '…'` if git isn't there yet.
Clone the other repos into `~/git/<name>` by hand — after that,
`scripts/bash/sync_repos.sh` pulls them all and enforces `.gitignore` (`.claude`,
`.DS_Store`) and the LF `.gitattributes`.

## Dotfiles

`nix/nixos/desktop/xdg.nix` sets the XDG base dirs and redirects every app that
honours an env var. What's left at `$HOME` root as a dotfile is either
XDG-native (`.config`, `.local`, `.cache`, `.ssh`) or an upstream bug —
`xdg-ninja` lists them; steam, factorio, mixxx and stepmania are not fixable
from here.

Migrations to those new paths are done by `home_setup.sh`, which leaves a
symlink at the old location so a running gpg-agent doesn't break mid-session.

There is no home-manager. Everything under `git/dots/config/` reaches
`~/.config/` as a plain symlink, and **`scripts/bash/home_setup.sh` is the only
place that mapping is written down** — a new directory in `config/` is not live
until it is listed in the `CONFIGS` array there. Run the script after adding
one; it is idempotent and dry-run by default.

Three cases it handles that a `ln -s` loop would get wrong:

- **VSCodium is linked per file**, not as a directory — `~/.config/VSCodium`
  also holds `Cache/`, `Cookies` and `workspaceStorage/`, so linking the
  directory hands the whole profile to git and breaks the editor.
- **A real directory is never clobbered.** If `~/.config/<app>` exists as
  actual files, the script warns and leaves it; you reconcile it by hand.
- **Dead links into this repo are pruned.** Delete something from `config/` and
  the orphaned link in `~/.config` goes with it on the next run. Broken links
  pointing anywhere else are only reported — they are not ours to remove.

## Working fast

Both editors and the file manager are pointed at this layout:

- `yazi` — `g` then `g d f n b a w c` → git, dots, flakes, notes, ben,
  archive, downloads, config. (`z`/`Z` are still zoxide and fzf.)
- `nvim` — `<leader>h` + the same letters, each one `tcd`s the tab and opens
  the file picker there. `<leader>fp` picks a repo by name instead.
  `<leader>nm` opens `notes/main.md`, `<leader>;` drops into yazi at cwd.
- `z <name>` (zoxide) beats both once a path is warm.
- `check_repo` runs on shell start and flags uncommitted/unpushed work across
  dots, notes, sakuhin and pass. It resolves each by name against `~/git`,
  `~/ben` and `~` rather than by path, so it survives a move.
- `nix-clean [-n] [keep]` prunes system generations (default: keep 2) and then
  collects garbage. Order matters — GC alone reclaims almost nothing while old
  generations still root what they reference. `nix-roots` shows what is still
  holding the store open when a pass frees less than expected; it is usually a
  `result` symlink in a project directory.

## Adding something new

1. Can it be committed? → `~/git/<name>`, flat, lowercase.
2. Would losing it be unrecoverable? → `~/ben/`.
3. Is it finished and large? → `~/archive/<existing category>/`.
4. None of the above? → it's not a new top-level folder. It's either a
   subfolder of one of the seven, or it's `~/downloads/` and you haven't
   decided yet.

Rule 4 is the whole discipline. `other/`, `misc/`, `temp/`, `stuff/` and
`1_fix/` are banned names — each one is a decision deferred, and deferred
decisions are what turned a sixth of this disk into a folder nobody could
describe.
